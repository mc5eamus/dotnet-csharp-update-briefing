Why the days split this way

The obvious split — one release per day — happens to also be the useful one, because it maps onto a real decision boundary rather than an arbitrary version number.

Those are different conversations, so they get different days. Day 1 is stable and immediately actionable. Day 2 is forward-looking, still moving, and ends in a decision.

Both days are timed against their real slide counts

Neither day is rounded up. Day 1 and Day 2 each carry 84 content slides, and every module above is budgeted at the pace those slides actually take — which is how both reach roughly four hours before a single lab starts. Day 2 is an RC release, so it is also the day with the most “we measured this ourselves” content.

What's in scope — and what isn't

This workshop was shaped by your team's survey, so it is deliberately narrower than a general "what's new" tour.

In focus
  • EF Core — complex types, JSON columns, query translation, migrations
  • ASP.NET Core — OpenAPI 3.1 and 3.2, validation, Minimal APIs
  • .NET libraries — post-quantum cryptography, System.Text.Json, compression, diagnostics
  • The languages — C# 14 and C# 15
Deliberately excluded
  • MAUI, Windows Forms, WPF
  • Blazor
  • F#, VB.NET

Worth knowing: roughly half of the official ASP.NET Core release notes for both releases is Blazor content. All of it has been filtered out here, which is why this covers more of what you actually use in less time.

.NET 12

There is a short outlook at the end of Day 2. Be aware that no .NET 12 documentation or preview exists yet — previews are expected to start in early 2027 — so that module covers directional signals and planning, not features. Anything you read online today claiming .NET 12 feature detail is speculation.

Before you arrive

The labs are hands-on. Please install these ahead of time.

InstallWhy
.NET 10 SDKDay 1 labs target net10.0
.NET 11 SDK (RC 1 or later)Day 2 labs target net11.0
An editorVisual Studio 2026, VS Code with the C# Dev Kit, or Rider
Install both SDKs — 11 alone is not enough

The .NET 11 SDK ships only net11.0 templates, so this fails on a machine that only has .NET 11:

dotnet new console --framework net10.0
# error: 'net10.0' is not a valid value for --framework

The .NET 11 SDK can happily build an existing net10.0 project — it just can't scaffold one. SDKs install side-by-side and won't disturb each other.

Optional, for full coverage

  • Post-quantum cryptography needs OpenSSL 3.5+ or Windows CNG with PQC support. Lab 02 gates on IsSupported and still works if an algorithm is missing — which is realistic, because on Windows 11 25H2 ML-KEM and ML-DSA are available but SLH-DSA is not.
  • SQL Server vector search needs Azure SQL or SQL Server 2025. The runnable EF labs use SQLite; vector and JSON-index topics are walkthroughs.
